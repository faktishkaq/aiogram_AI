## 1. Изучение предметной области

### 1.1. Описание

Предметная область — управление кинотеатром: в залах идут сеансы фильмов, продаются билеты на конкретные места. Цена билета зависит от типа места и сеанса. Зритель видит афишу, схему зала и свободные места; администрация — выручку и заполняемость.

### 1.2. Роли, участвующие в процессах

| Роль | Кратко |
|---|---|
| Зритель | Покупает и просматривает билеты |
| Кассир | Оформляет продажу и возврат в кассе |
| Администратор | Управляет фильмами, залами, сеансами, отчётами |

### 1.3. Ключевые процессы

#### Процесс P1. Планирование сеанса

1. **Кто:** администратор.  
2. **Что делает:** выбирает фильм, зал, дату/время, задаёт базовую цену.  
3. **Порядок:** выбирает фильм из проката → проверяет, что зал свободен на интервал → задаёт время начала/окончания и цену → сохраняет сеанс.  
4. **Что меняется в данных:** появляется запись «Сеанс»; статус сеанса = «запланирован».

#### Процесс P2. Продажа билета

1. **Кто:** зритель (онлайн) или кассир (в кассе).  
2. **Что делает:** выбирает сеанс и свободные места, оформляет покупку.  
3. **Порядок:** поиск сеанса → просмотр схемы зала → выбор свободных мест → расчёт цены (базовая цена × коэффициент типа места) → оплата → выдача билета.  
4. **Что меняется в данных:** создаются записи «Билет» со статусом «продан»; выбранные места считаются занятыми на этот сеанс.

#### Процесс P3. Возврат билета

1. **Кто:** зритель или кассир.  
2. **Что делает:** аннулирует ранее проданный билет.  
3. **Порядок:** находит билет → проверяет, что возврат ещё разрешён → меняет статус на «возвращён».  
4. **Что меняется в данных:** статус билета → «возвращён»; место снова свободно на сеанс.

#### Процесс P4. Просмотр афиши и свободных мест

1. **Кто:** зритель, кассир.  
2. **Что делает:** смотрит сеансы на дату и схему занятости зала.  
3. **Порядок:** выбор даты/фильма → список сеансов → открытие схемы зала сеанса.  
4. **Что меняется в данных:** только чтение (сеансы, места, билеты).

#### Процесс P5. Отчёт по заполняемости и выручке

1. **Кто:** администратор.  
2. **Что делает:** считает заполняемость сеанса и сумму продаж.  
3. **Порядок:** выбор периода/сеанса → агрегация проданных билетов → вывод заполняемости и выручки.  
4. **Что меняется в данных:** только чтение и агрегация.

### 1.4. Ограничения

| Тип | Ограничение | Как реализуется (ориентир) |
|---|---|---|
| Структурные | У каждого сеанса есть фильм и зал | NOT NULL, FK |
| Структурные | У каждого места есть зал и тип места | NOT NULL, FK |
| Бизнес-правила | Нельзя продать одно место на один сеанс дважды | частичный UNIQUE / логика приложения |
| Бизнес-правила | Сеансы в одном зале не пересекаются по времени | триггер / логика приложения |
| Бизнес-правила | Место в билете принадлежит залу сеанса | триггер / логика приложения |
| Бизнес-правила | Цена билета и базовая цена сеанса ≥ 0 | CHECK |
| Технические | Пара (ряд, номер) уникальна в пределах зала | UNIQUE |
| Технические | Логин сотрудника уникален | UNIQUE |

**Источники ограничений:** логика процесса (нельзя вернуть не проданный билет); физическая реальность (одно место — один зритель на сеанс); бизнес-политика (цена зависит от типа места и сеанса).

## 2. Роли пользователей

Роль — набор прав и действий для типа пользователя (не конкретный человек).

### 2.1. Администратор

| Действие | Входные данные | Результат в данных | Ограничения |
|---|---|---|---|
| Добавить/изменить фильм | название, длительность, рейтинг, жанр | запись «Фильм» создана/изменена | длительность > 0 |
| Настроить зал и места | название зала, ряды/номера, типы мест | записи «Зал», «Место», «Тип места» | (ряд, номер) уникальны в зале |
| Создать сеанс | фильм, зал, время начала/конца, базовая цена | запись «Сеанс» | нет пересечения сеансов в зале; конец > начала; цена ≥ 0 |
| Отменить сеанс | id сеанса | статус сеанса = «отменён» | нельзя отменить, если уже идут необработанные продажи без политики возврата |
| Смотреть отчёты | период, фильтр по залу/фильму | только чтение: выручка, заполняемость | — |
| Управлять сотрудниками | ФИО, логин, роль | запись «Сотрудник» | логин уникален |

### 2.2. Кассир

| Действие | Входные данные | Результат в данных | Ограничения |
|---|---|---|---|
| Найти сеанс | дата, фильм, зал | список сеансов (чтение) | — |
| Посмотреть свободные места | id сеанса | схема зала с занятостью (чтение) | — |
| Продать билет | сеанс, место(а), данные зрителя (опц.) | билет(ы) со статусом «продан» | место свободно; сеанс не отменён; цена ≥ 0 |
| Вернуть билет | id билета | статус = «возвращён» | билет был «продан»; возврат в допустимый срок |
| Выдать/напечатать билет | id билета | факт продажи зафиксирован (чтение/печать) | билет существует и активен |

### 2.3. Зритель (клиент)

| Действие | Входные данные | Результат в данных | Ограничения |
|---|---|---|---|
| Смотреть афишу | дата, жанр/фильм | список сеансов (чтение) | — |
| Выбрать места на схеме | id сеанса | список свободных мест (чтение) | видны только свободные |
| Купить билет(ы) | сеанс, места, ФИО/телефон/email | билеты «продан» + при необходимости «Зритель» | место не занято; контакты корректны |
| Смотреть свои билеты | id зрителя / контакты | список билетов (чтение) | только свои билеты |
| Отменить покупку | id билета | статус «возвращён» (если разрешено) | только свои; в срок отмены |

## 3. Бизнес-правила

Бизнес-правило — утверждение, которое в данных должно быть истинно всегда.  
Шаблон: «[условие] должно / не должно выполняться».

Для учебного проекта — **7 правил**, покрывающих ключевые процессы продажи, планирования сеансов и целостности мест.

| № | Правило (язык предметной области) | Категория | Где реализуется |
|---|---|---|---|
| BR-1 | На один сеанс одно и то же место **не должно** быть продано более одного раза (среди билетов со статусом «продан» или «забронирован») | ограничение состояния / уникальности | частичный UNIQUE или логика приложения |
| BR-2 | Базовая цена сеанса и цена билета **должны** быть ≥ 0 | ограничение значения | CHECK |
| BR-3 | Дата-время окончания сеанса **должна** быть строго позже даты-времени начала | ограничение по времени | CHECK |
| BR-4 | Место в билете **должно** принадлежать залу того сеанса, на который оформлен билет | ограничение ссылки / состояния | триггер или логика приложения |
| BR-5 | В одном зале сеансы **не должны** пересекаться по времени | ограничение состояния | триггер или логика приложения |
| BR-6 | В пределах одного зала пара (ряд, номер места) **должна** быть уникальна | ограничение уникальности | UNIQUE |
| BR-7 | Статус билета **должен** принимать только значения: «продан», «забронирован», «возвращён»; билет со статусом «возвращён» **не должен** считаться занимающим место | ограничение значения / состояния | CHECK + логика учёта занятости |

### Связь правил с процессами

| Процесс | Какие правила защищают |
|---|---|
| P1. Планирование сеанса | BR-2, BR-3, BR-5 |
| P2. Продажа билета | BR-1, BR-2, BR-4, BR-7 |
| P3. Возврат билета | BR-7 |
| P4–P5. Афиша и отчёты | опираются на корректность BR-1, BR-7 при подсчёте свободных мест / выручки |
